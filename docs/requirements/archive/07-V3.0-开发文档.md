## 2. 核心原则（V3.0，11 条）

基本同 V2.0（只做两件事 / 只采用 TON / 开发者不参与运营 / 资金代码管 / 签名在用户设备 / 免保证金 /
单笔限制 / 群成员投票 / 仲裁员质押 / 人性化保障 / 防黑产），未逐条变化。

## 3. 架构（V3.0 五进程）

```
用户(Telegram) → Bot进程(命令分发/权限/限流 + 群管理 + 交易入口)
              → Admin API(业务逻辑/信用分/担保交易/投票/仲裁)
              → Worker(异步任务/队列/定时/链上事件监听)
              → Web后台(Vue 3：管理面板/交易界面/审批中心/规则配置)
              → 基础设施(MySQL │ Redis │ Kafka │ TON │ TON Pay)
```

> 整理注：此架构与 `docs/requirements/06-架构与工程实践.md` 的 Sola 五进程一致——即 V3.0 已采纳该建议。
> 项目现状是**单一 Spring Boot 应用**（`tgg-app`），且**尚无任何 Web 层**（见第五节 S6）。

## 6. 整理观察（补充，非原文）

### 6.1 ⚠️ 编号重排切断了两处既有引用（必须处理）
项目**已落地的代码与文档**用的是 V2.0 编号，V3.0 重排后**T31 之后全部错位**。两处已实际受影响：
1. **`TradeStage`（交易阶段标注）**：项目代码注释与 `FEATURE-ROADMAP.md` 里记为 **T38**；
   但按 V3.0，**T38 是「投票奖励分配」**，交易阶段标注应为 **T40**。
2. **防钓鱼提示**：`FEATURE-ROADMAP.md:136` 记为 **T42**（V2.0）；V3.0 的 T42 是「链上存证」，
   防钓鱼提示应为 **T44**。第六份整理（`06-架构与工程实践.md`）里「T42/T55 加 permit 提示」的引用，
   按 V3.0 应读作 **T44/T55（Permit 警示为 T64）**。

**建议（供决策）**：
- ① **不要再重排编号**——每重排一次，全项目的编号引用都要重映射一遍，成本高且易错；
- ② 现有代码注释**保留 V2.0 编号并加注 `(V2.0 编号；V3.0 见 T40/T44)`**，不为此改代码；
- ③ 今后**引用编号一律标注版本**（如 `T40(V3.0)`），本表作为唯一映射依据。

### 6.2 Ephemeral Messages 已核实为真实能力，但 V3.0 未给编号
V3.0 在「核心规则」与「交互设计」里两处提到 **Ephemeral Messages**（维护期倒计时等隐私通知用临时消息），
但**模块清单里没有对应功能编号**。核实：这是 Telegram **Bot API 10.2/10.3（2026-07）**的真实能力——
群里机器人可发**仅单个成员可见**的消息（`is_ephemeral` / `ephemeral_message_parameters`，
有 15 秒规则、`message_id` 为 0）。**建议**给它一个编号（否则实现时会漏），并明确归属（T50 主动推送 / T51 争议陈述相关）。

### 6.3 前六份材料已被 V3.0 吸收，但其中三处风险未随之进正文
- **助记词冲突**（`05`）：市面 Fragment SDK 要求 TON 钱包助记词——V3.0 核心规则只写「Fragment API：用 TON 直接购买 Stars/Premium，**无需 API Key**」，
  **没有提"需要助记词"**这一点。若不注明，实现者可能照 V3.0 直接选型，撞上「服务器不碰私钥」红线。
  已在待决 **H 节**记录，建议正文补一句。
- **Web 端点缺口**（`03`）：V3.0 的五进程架构**已包含 Web 后台与 Admin API**，等于承认了该层——
  但项目**当前仍是零 Web 层**（见 `FEATURE-ROADMAP.md` 的 S6）。
- **存储费池 / Gas 报告**（`04`/`06`）：V3.0 未提 `storageFund`，而 TON 合约存储费是硬约束（余额耗尽会冻结）。

### 6.4 与项目现状的差距
- 群管理：G5/G7/G9/G10/G22/G23/G24/G26/G28/G29 + G11/G12/G13/G14/G15/G19/G27 已落地；

  其中 **T38（V2.0）= T40（V3.0）交易阶段标注**已在代码里实现；
- 其余（含 V3.0 全部新增 6 项、Web 层、合约）未做。
