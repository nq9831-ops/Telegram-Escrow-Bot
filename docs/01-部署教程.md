# tgg-escrow 部署教程（宝塔面板版）

> 零基础的话，先看同目录的《00-手把手部署-大白话版.md》——那本每一步只讲「点哪里、填什么、
> 看到什么算成功」。这本是详细版：每步为什么这么做、命令是什么、出问题怎么查，都写全了，
> 适合边做边看，也适合以后回来查。
>
> 全文的章节号是固定的（比如「6.3 节」「第 11 章」「附录 A」），别的文档里提这些编号时，
> 指的就是这里。面板菜单文案在不同版本里可能略有差异，**功能一样就说明是同一个入口**。

## 第 0 章 这套系统是什么（部署前看一眼）

一句话：这是一个跑在 Telegram 里的**担保交易机器人**。买卖双方在 Telegram 里建单，
买家的钱锁在 **TON 区块链上、这笔订单专属的合约**里，之后按流程放款、退款或走争议裁决。

```
                    Telegram
  ┌───────────────┐    ┌──────────────────┐
  │ 用户（买方）   │    │ 用户（卖方）      │
  └──────┬───────┘    └────────┬─────────┘
         │  /escrow 命令 &       │
         │  Mini App（HTTPS）    │
         ▼                      ▼
  ┌───────────────────────────────────────┐
  │ 宝塔面板服务器                           │
  │  · Java 项目管理器 → tgg-app（8080）      │
  │  · Nginx 反向代理 + Let's Encrypt SSL    │
  │  · MySQL 8（订单/账本/信用等）            │
  │  · 计划任务（心跳对账 / 备份）             │
  └───────────────┬───────────────────────┘
                  │
                  ▼
        TON 区块链：每笔订单一个托管合约（应用在用户钱包签名后自动部署）
```

动手前，先记住四件事：

1. **合约不用你一个个部署**。每笔订单的托管合约，都是买家自己钱包签名后、程序自动部署的。
   你要准备的只是那个**治理钱包**（负责升级合约），合约文件已经内置在程序里了。
2. **有测试网和主网两个环境**。默认就是测试网，强烈建议先在测试网把全流程跑通，再切主网。
3. **Mini App 必须上 HTTPS**。用面板一键签一张 Let's Encrypt 证书就行（6.5 节）。
4. **绑域名和加反向代理是两步，都要做**。只绑域名等于只挂了门牌号没接电线，
   访问会得到 **403**——这是用面板部署最常见的翻车点，6.4 节有完整步骤。

## 第 1 章 开工前要准备什么

| 项目 | 要求 | 去哪弄 |

## 第 2 章 服务器和面板，装起来

### 2.1 安装宝塔面板

到宝塔官网（bt.cn），选你服务器的系统版本，复制**安装命令**，在服务器上执行。
装完按屏幕提示进面板，把面板地址、端口、账号密码记好。

### 2.2 装 Nginx 和 MySQL 8

面板左栏 → **软件商店**，把 **Nginx**（任意稳定版）和 **MySQL 8.x** 装上。
云服务器别忘了在云厂商的**安全组**里放行端口（80、443，以及面板自己的端口）。

### 2.3 装 Java 项目管理器和 JDK 21

1. 面板 → **软件商店** → 装 **Java 项目管理器**（用它来托管我们的 jar 程序）。
2. 面板 → **网站 → Java 项目**（或者在软件商店里）→ **JDK 管理** → 装 **jdk-21**。
   装过 `jdk-21.0.2` 的话这里会直接显示已安装。
   > 这套程序锁死 Java 21。别用 8/11/17 去跑，起不来，还会报 `UnsupportedClassVersionError`。

### 2.4 （可选）先自检

面板 → **终端**里跑一下：

```bash
nginx -v && mysql --version
/www/server/java/jdk-21*/bin/java -version   # 路径以实际安装为准；应显示 21.x
```

## 第 3 章 建数据库

面板 → **数据库** → **添加数据库**：

- 数据库名：`tgg_escrow`；用户名：`tgg`；密码：点「随机」生成强密码，**记下来**；
- 权限：选 **本地服务器（127.0.0.1）**，不要选「所有人」；
- 字符集：`utf8mb4`。

建好之后把 库名/用户名/密码 记好，6.2 节填 env 时要用。

> 表不用你建。程序第一次启动时会自己把表全部建好（日志里能看到
> `Successfully validated 17 migrations` 这类字样）。

## 第 4 章 申请 Telegram 机器人

1. 在 Telegram 里找 **@BotFather** → 发 `/newbot` → 跟着提示走 → 拿到 **Token**
   （长这样：`123456789:AA...`）。**Token 只能放在服务器 env 文件里，别贴到任何聊天或仓库**。
2. `/setname`、`/setdescription`、`/setabouttext` 这些都是可选的装饰，想弄就弄。
3. **设置命令菜单**：BotFather → `/setcommands` → 选你的 bot → 粘贴：

```
escrow - 托管交易（下单/托管/交付/放款/退款/争议/查询）
```

4. **设置 Mini App 按钮**（推荐做）：BotFather → `/newapp` → 选你的 bot → 标题随意 →
   **Web App URL 填 `https://你的域名`**。注意必须是 https，所以域名这块先把 6.5 节做完；
   暂时没有也可以以后再设。
5. 把 **Bot 用户名**（不带 @）记下来，填到 env 的 `TELEGRAM_BOT_USERNAME`。

## 第 5 章 TON 那边要准备什么

### 5.1 选网络

- **测试网（testnet）**：先在它上面把全流程跑通。env 里 `TGG_CHAIN_TESTNET=true`（默认值就是它），
  测试币去 TON 官方测试网水龙头领。
- **主网（mainnet）**：正式运营时把 `TGG_CHAIN_TESTNET` 设成 `false`。
  > 注意：默认是 true（测试网）。要上主网必须**明确写** `false`，不是删掉就完事。

### 5.2 治理钱包——一步步来

**先说它是干嘛的**：这个钱包不碰用户的钱。它只干两件事：一是**联邦**，
合约里认它的签名来批准争议裁决；二是**升级**，将来给合约换代码时由它签名。
所以它像一枚公章：丢了，合约就永远升不了级；泄露了，别人就能发起升级。
必须按公章的标准保管。

**第 1 步：创建钱包（两种方式任选）**

*方式 A：手机 App（推荐，最简单）*
1. 装一个支持 **V5(R1) 协议的 TON 钱包**（现在主流的钱包默认就是 V5）；
2. **新建一个钱包**（别用存资产的老钱包）；
3. **24 个英文单词用笔抄在纸上，抄两份分开存**——这是钱包唯一的恢复手段；
   如果 App 提示「云端备份」，要知道那等于把助记词交给第三方服务器，自己权衡；
4. 在 App 里把钱包**地址**复制下来（`EQ` 或 `kQ` 开头都行，后面的自检工具两种都认）。

*方式 B：命令行党（acton，和系统工具链同源）*
有 TON 工具链的可以用 `acton wallet new` 创建、`acton wallet list` 看地址、
`acton export-mnemonic` 导出 24 词（默认参数就行）。

**第 2 步：用包里自带的小工具算出「地址 + 公钥 + walletId」**
这一步是核心——**多数手机 App 不显示公钥**，就用这个工具算。

前提：第 6 章的目录和 `env.sh` 已经弄好（助记词已经填进去了）。在服务器上执行：

```bash
cd /www/wwwroot/tgg
unzip -q -o tgg-app.jar 'BOOT-INF/*' -d /tmp/tgg-cls      # 第一次使用：从应用包里取出运行库
set -a; . ./env.sh; set +a                            # 导入环境（含助记词）
java -cp "/tmp/tgg-cls/BOOT-INF/classes:/tmp/tgg-cls/BOOT-INF/lib/*" scripts/wallet-selfcheck.java
```

输出大概长这样（**三样都记下来**）：

```
地址(kQ… 测试网形态): kQ……（主网会显示 EQ……）
walletId:        2147483645（网络默认值）
公钥(base64):    PInSwNS0……=
```

**第 3 步：把算出来的填回 env.sh**

| 工具的输出 | 填到 env.sh 的哪一项 |
|---|---|
| 24 词助记词 | `TGG_CHAIN_UPGRADE_WALLET_MNEMONIC=` |
| 地址 | `TGG_FEDERATION_ADDRESS=` |
| 公钥 | `TGG_FEDERATION_PUBLIC_KEY=` |
| walletId | `TGG_CHAIN_UPGRADE_WALLET_ID=`（等于网络默认值时可以不填） |

**第 4 步：对拍（强烈建议做，2 分钟，能省掉最难查的坑）**
拿**手机钱包里显示的地址**来对一下：

```bash
TGG_EXPECTED_WALLET_ADDRESS="<App 里复制的地址>" \
  java -cp "/tmp/tgg-cls/BOOT-INF/classes:/tmp/tgg-cls/BOOT-INF/lib/*" scripts/wallet-selfcheck.java
```

- 显示 `✅ 对拍一致`：助记词、walletId、地址三者配套，放心往下走；
- 显示 `⚠️ 不一致`：工具会**自动扫描**并告诉你正确的 walletId，照它说的填；还不行就查两条：
  助记词是不是抄错了、钱包是不是 V5(R1)（老的 V3/V4 协议不兼容）。

> 为什么较这两分钟的真：钱包三要素只要错一个，**症状就是「签名被拒、升级发不出去」**——
> 这是最难排查的故障类型，在这里先掐掉。

**第 5 步：给钱包留点余额**
转 3–5 个 TON 进去（主网真币；测试网去领测试币）。这是升级提案和应用消息的手续费，大约每笔 0.2 TON。

**进阶：治理冷热分离（可选，正式运营推荐）**
1. 另外建一个**离线身份钱包**（助记词只存离线设备或纸上，永远不进服务器）；
2. 在离线机器上用同一套工具算出它的**公钥**；
3. env 里设置 `TGG_CHAIN_GOVERNANCE_MODE=offline`、`TGG_CHAIN_GOVERNANCE_PUBLIC_KEY=<离线身份公钥>`、
   `TGG_CHAIN_GOVERNANCE_WALLET_ID=<对应的 walletId>`；
4. 效果：**服务器上不再有治理私钥**，就算被入侵也夺不走治理权；升级消息改成离线机签名、
   服务器只负责广播。

**几个常踩的坑（避开就行）**
- **walletId 拍脑袋填** → 症状是「钱包拒绝一切签名」。永远用工具算出来的值。
- **助记词截屏、发聊天、存网盘** → 等于公章到处乱放。只抄纸、离线存。
- **测试网配好直接切主网** → 助记词一样，但 **walletId 和地址前缀会变**
  （主网 EQ/2147483409，测试网 kQ/2147483645）。切网络后用工具重算一遍再填。
- **用老钱包（V3/V4）** → 不兼容，必须是 V5(R1)。

### 5.3 USDT（jetton）结算（可选）

把 `TGG_CHAIN_JETTON_MASTER` 填成**主网 USDT 的 jetton master 地址**。
到 tonviewer.com 搜「USDT」核对官方合约地址，**务必防假币**。
测试网演练就用测试网的 jetton（或者先只用 TON 跑）。

### 5.4 裁决三方签名（可选）

`TGG_VERDICT_BUYER_PUBLIC_KEY` / `TGG_VERDICT_SELLER_PUBLIC_KEY` 填双方公钥。
不配置的话裁决路径是关闭的（fail-closed），争议就只能走协商或逃生票。

### 5.5 合约资源说明（不用你操作）

合约编译好的文件已经内置在 `tgg-app.jar` 里，带哈希校验。本包 `contracts/` 里放的是源码和产物，
给你审计用。只有要改合约时才需要自己编译：用 Acton 1.2.0，编译产物的哈希必须和
`contracts/escrow-resources/EscrowContract.hash` 一致；**换掉内嵌资源后必须重新打包 jar**，
否则链上会部署旧代码（症状见第 11 章那条「0xFFFF bounce」）。

## 第 6 章 把程序部署上去（宝塔面板主线）

### 6.1 上传程序和配置

1. 面板 → **文件** → 进到 `/www/wwwroot/` → 新建目录 `tgg/`。
2. 把部署包里的 `app/tgg-app.jar` **上传**到 `/www/wwwroot/tgg/`。
3. 把 `config/env.example.sh` 的内容在本地填好（怎么填看 6.2 节），用面板的文件编辑器
   在 `/www/wwwroot/tgg/` 新建 `env.sh`，粘贴保存。然后在终端里：

   ```bash
   chmod 600 /www/wwwroot/tgg/env.sh   # 敏感文件仅 root 可读
   ```

### 6.2 填写 env.sh（对照 config/env.example.sh 模板）

**至少要填这几组**（每一项的详细说明看模板里的注释）：

| 组 | 要点 |
|---|---|
| 数据库 | HOST=`127.0.0.1`、PORT `3306`、NAME/USER/PASSWORD 用第 3 章建的 |
| Telegram | `TELEGRAM_BOT_TOKEN`、`TELEGRAM_BOT_USERNAME` |
| Web | `TGG_WEBAPP_URL=https://你的域名` |
| 管理 | `TGG_ADMIN_USERNAME` / `TGG_ADMIN_PASSWORD`（**强随机密码**，它保护所有 /admin 功能） |
| 链 | `TGG_CHAIN_TESTNET`（先保持 true 演练）、`TGG_CHAIN_UPGRADE_WALLET_MNEMONIC`、`TGG_FEDERATION_ADDRESS`、`TGG_FEDERATION_PUBLIC_KEY`；收 USDT 再加 `TGG_CHAIN_JETTON_MASTER` |

### 6.3 创建 Java 项目（交给面板托管）

面板 → **网站 → Java 项目 → 添加 Java 项目**：

| 格子 | 填什么 |
|---|---|
| 项目名 | 随手起，建议 `tgg-bot` |
| 项目路径 | `/www/wwwroot/tgg` |
| jar 路径 | `/www/wwwroot/tgg/tgg-app.jar` |
| **JDK** | **jdk-21**（2.3 节装的） |
| 端口 | **8080**（先确认没被占：面板安全页看一眼，或终端 `ss -ltn \| grep 8080`） |
| 运行用户 | `root`（想用 `www` 也行，用哪个就把 6.1 节的文件属主改成哪个） |
| **启动命令** | **清掉自动生成的，换成下面这一行** |

启动命令（**一行照抄**，路径按实际情况微调）：

```bash
bash -c 'set -a; . /www/wwwroot/tgg/env.sh; set +a; exec /www/server/java/jdk-21.0.2/bin/java -Xmx768m -Xms256m -jar /www/wwwroot/tgg/tgg-app.jar --server.port=8080'
```

> **为什么要用自定义启动命令**：这行命令先把 `env.sh`（里面是 Token、助记词这些敏感值）
> 读进程序的环境里，面板配置里只出现文件**路径**、不出现任何密钥值。
> 这是最稳的密钥注入方式，也不受面板版本差异影响。

保存后项目会自动启动。**注意：项目建好不等于部署好了**——必须做 6.4 节的验证。

### 6.4 域名和反向代理（**两步都要做**，少了第二步就是 403）

**第一步：绑域名**（Java 项目 → 域名管理，或创建时填）：填 `你的域名`。

**第二步：加反向代理**（这一步才是真正的「接线」）：

- 方式 A（推荐）：**网站 → 反向代理 → 添加反向代理**：
  - 代理名称：`tgg-bot`；目标 URL：`http://127.0.0.1:8080`；发送域名：`$http_host`；
  - 域名：`你的域名`。
- 方式 B：在 **Java 项目的「反代/proxy」配置**里加：端口 `8080`、路径 `/`。

**验证一下接线成功没有**（终端）：

```bash
grep -r "proxy_pass" /www/server/panel/vhost/nginx/ 2>/dev/null | grep 8080
# 应该能看到一行 proxy_pass http://127.0.0.1:8080 —— 有就是对的；没有就回第二步补
```

> 这就是那个最有名的坑：只绑域名不加反代，nginx 对 8080 直接甩 403。

### 6.5 HTTPS（Let's Encrypt 一键签）

面板 → **网站** → 找到这个站点 → **SSL** → **Let's Encrypt** → 勾上域名 → 点申请（1 分钟）。
成功后打开「**强制 HTTPS**」。（前提是域名解析已经生效。）

然后把 `env.sh` 里的 `TGG_WEBAPP_URL` 写成 `https://你的域名`，回 Java 项目
**重启**一次（让程序读到新配置）。

## 第 7 章 检查它真的活了（必做）

### 7.1 面板上的状态

面板 → **网站 → Java 项目** → 你的项目：状态应该是**运行中**，**8080** 在监听。
如果显示「未启动/已停止」或者反复重启，直接去第 11 章查。

### 7.2 看日志（面板里直接看）

Java 项目详情里能看到**日志文件路径**（一般在 `/www/wwwroot/tgg/` 或面板日志目录）。
正常的话，从上到下会依次出现：

1. `Starting EscrowBotApplication ... using Java 21` — 进程起来了
2. `HikariPool-1 - Start completed` — 数据库连上了
3. `Successfully validated 17 migrations` — 表结构没问题（第一次部署会有一些 `Migrating`）
4. `Connected to lite-server ...` — TON 轻节点连上了
5. `Tomcat started on port 8080` — Web 服务就绪
6. `Started EscrowBotApplication in ~80 seconds` — **启动完成**（第一次约 1–2 分钟，正常）

### 7.3 端点检查（终端里跑）

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/                  # 302
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/miniapp/index.html  # 200
curl -s -o /dev/null -w '%{http_code}\n' -X POST http://127.0.0.1:8080/admin/reconcile  # 401（未认证被拒=fail-closed，正确）
curl -s -o /dev/null -w '%{http_code}\n' https://你的域名/miniapp/index.html      # 200（经面板反代+SSL）
```

### 7.4 Telegram 那边冒烟

私聊你的 Bot：`/start`（有欢迎语）→ `/escrow`（回一大段命令用法）→ 打开 Mini App（做完 4.4 节后）能加载。

## 第 8 章 两个定时任务（面板「计划任务」）

> 都在 **面板 → 计划任务 → 添加任务** 里配，类型选 **Shell 脚本**。

### 8.1 对账心跳（**强烈建议**，每 10 分钟一次）

任务名 `tgg-heartbeat-10m`，周期「N 分钟 = 10」，脚本内容（**照抄**）：

```bash
set -a; . /www/wwwroot/tgg/env.sh; set +a; TGG_ADMIN_USER="${TGG_ADMIN_USERNAME}" TGG_ADMIN_PASS="${TGG_ADMIN_PASSWORD}" bash /www/wwwroot/tgg/heartbeat.sh >> /www/wwwroot/tgg/heartbeat.log 2>&1
```

先把脚本放到位：

```bash
cp <部署包>/scripts/heartbeat.sh /www/wwwroot/tgg/heartbeat.sh && chmod 755 /www/wwwroot/tgg/heartbeat.sh
```

**先手动跑一次**看看（终端）：

```bash
set -a; . /www/wwwroot/tgg/env.sh; set +a
TGG_ADMIN_USER="${TGG_ADMIN_USERNAME}" TGG_ADMIN_PASS="${TGG_ADMIN_PASSWORD}" bash /www/wwwroot/tgg/heartbeat.sh
# 期望看到：{"ok":true,"mode":"batch","total":N,"dangers":[]} + notify-timeouts 的回执；退出码 0
```

> 退出码的意思：`0` 正常；`2` 有 DANGER（资金异常，要人工去查）；`3` 响应解析不了（去看日志）。
> 脚本里的变量名是 `TGG_ADMIN_USER/PASS`，所以上面用了「先读 env.sh、再设别名」的写法——
> 这样密钥不会出现在任务配置里。

### 8.2 数据库备份（每天）

任务名 `tgg-db-backup-daily`，周期「每天 04:30」。先把 `backup-db.sh` 头部注释里说的
mysql 凭据文件路径填好，然后粘脚本：

```bash
cd /www/wwwroot/tgg && ./backup-db.sh >> /www/wwwroot/tgg/backup.log 2>&1
```

> 备份文件里有全部订单数据，保护级别和 env.sh 一样。每天去「计划任务→日志」看一眼有没有成功；
> 另外建议定期把备份再同步一份到对象存储之类的地方。

## 第 10 章 日常怎么管它

### 10.1 日志

- **应用日志**：Java 项目详情里有路径，面板能直接看/下载；终端 `tail -f` 也行。
  > 小提示：app.log 里可能混有二进制片段，用 grep 查的时候加 `-a`
  > （比如 `grep -a "Started" app.log`）。
- **nginx 日志**：面板 → 网站 → 站点 → 日志（访问和错误分开）。网站访问有问题先看这里。

### 10.2 重启

- 面板 → Java 项目 → **重启**按钮。
- **影响**：重启期间（约 80–90 秒）Mini App 和 Bot 暂时不能用；链上资金不受影响，放心。

### 10.3 更新程序（**严格按「先停 → 再换 → 后启」**）

1. 面板 → Java 项目 → **停止**（等状态变成「已停止」）；
2. 面板 → 文件 → 先把现行的 jar 改个名备份（比如 `tgg-app.jar.bak-日期`）；
3. 上传新的 `tgg-app.jar` 覆盖，确认属主和权限（`chmod 644`）；
4. 面板 → Java 项目 → **启动**；
5. 按 7.2 节和 7.3 节再验一遍。

> **为什么强调顺序**：别「先换后停」。进程还在跑的时候覆盖 jar，旧进程退出时会甩出一堆
> `ClassNotFoundException: Lifecycle$SingleUse` 之类的报错——无害，但特别吓人。先停就干净。

### 10.4 升级合约（改合约代码时才用）

每笔订单的合约地址不变、代码可以升级（72 小时冷静期 + 逃生票双保险）：

1. **提案**（ProposeUpgrade）：用治理钱包对目标合约发新代码的哈希，倒计时开始；
2. **72 小时冷静期**：期间可以 `cancel` 撤回；万一合约有问题，用户手里有**逃生票**
   （双方各投一票 = 全额退款）；
3. **应用**（ApplyUpgrade）：期满后发应用消息，合约切换新代码（地址、资金、状态全程保留）。

管理端点 `/admin/upgrade`（propose/apply/cancel/status/broadcast）可以查看和操作；
细节和安全注意事项见使用说明第 9 章。

## 第 11 章 出问题了对症查（面板版）

### 11.1 面板显示运行中，但域名访问不正常

| 症状 | 原因 | 怎么办 |
|---|---|---|
| **访问 403** | **只绑了域名没加反向代理**（最常见） | 加反代，目标 `http://127.0.0.1:8080`（6.4 节第二步）；用 `grep proxy_pass` 验证 |
| **访问 502** | 程序没起来 / 端口对不上 | 看 Java 项目状态和日志（第 7 章）；确认反代端口=程序端口 |
| 打开了但不是应用页面 | 反代目标错，或被别的站点截胡 | 检查站点列表里有没有重复域名；核对本站反代目标 |
| HTTPS 报证书错 | 证书没签/没续 | 面板 → SSL → Let's Encrypt 重新申请；开强制 HTTPS |

### 11.2 程序启动失败（对着日志找）

| 日志里长这样 | 原因 | 怎么办 |
|---|---|---|
| `Address already in use` | 8080 被占了 | `ss -ltn \| grep 8080` 找出占用者，杀掉或换端口（换了记得反代也改） |
| `UnsupportedClassVersionError` | JDK 版本不对 | Java 项目里把 JDK 改成 **jdk-21** |
| `Communications link failure` | 连不上 MySQL | 确认 MySQL 在跑、env 里数据库四项和第 3 章一致、用户权限限定 127.0.0.1 |
| `Flyway ... validate failed` | 数据库迁移文件被改过（校验和不符） | 恢复原迁移文件；**别改已发布的迁移**，要改就新增 V(n+1) |
| 配置缺失/环境变量没生效 | env 没被读进去 | 确认启动命令用的是 6.3 节那行自定义写法；重启项目 |
| `Update` 反序列化失败/请求被吞 | 误升了 Spring Boot 4.x（Jackson 版本冲突） | 锁回 3.5.16；用官方包就不用管这些 |
| 部署合约的交易 bounce `exit_code: 65535` | 应用里的合约资源和链上哈希不符（旧代码） | 用官方包，别手工替换内嵌资源；核对 `EscrowContract.hash` |
| 内存告警/GC 卡顿 | `-Xmx` 给小了 | 启动命令里调大，比如 `-Xmx1024m` |

### 11.3 跑着跑着的问题

| 症状 | 怎么办 |
|---|---|
| TON 查询偶尔 429 / Ratelimit | 公共 RPC 限速，正常波动（程序内置重试）；频率要求高就自建或买商用 RPC |
| Bot 没反应 | `curl https://api.telegram.org/bot<token>/getMe` 应该返回 bot 信息；检查服务器出网和 Token |
| initData 验签失败 | 域名必须 HTTPS；反代**不要改写/解码原始查询串**；服务器时钟用 NTP 校准 |
| 心跳退出码 2 | 有订单 DANGER（资金滞留或方向异常）——照告警提示人工核对链上和链下（`/escrow status` + 链上浏览器） |
| 「命令没反应」 | 程序/网络/群权限，三选一；先用 `/escrow status` 复核，再看 10.1 节的日志 |

## 第 12 章 安全清单（上线前挨个打勾）

**程序这边**：
1. `env.sh` 权限 **600**，绝不能进仓库、进聊天；密钥值只存在于这个文件。
2. **助记词离线双份备份**（纸或金属板）。服务器上只有「运行时持有」。丢了=合约永远升不了级；
   泄露=别人能升级——两种都严重。
3. **治理冷分离（推荐）**：正式运营时切 `TGG_CHAIN_GOVERNANCE_MODE=offline`，服务器上只留公钥。
4. 管理端点用强密码；`/admin/*` 建议**别对公网开放**（心跳从本机调用就够了；
   确实要外访，起码套一层 IP 白名单）。
5. 防火墙只开 443 和必要端口；8080 不要直接裸露到公网。
6. SSH 加固：密钥登录，禁 root 密码直登，上 fail2ban。
7. 备份文件和 env.sh 同级保护；再留一份在异地。

**面板这边**（一样重要）：
8. **面板入口**：改默认端口、开面板 SSL、配**授权 IP**（只让自己的 IP 能开面板）。
9. 面板账号强密码；别在浏览器里保存明文；不要把面板分享给别人。
10. 面板和商店里的组件及时更新；只从面板官方源装东西。

## 附录 A：不用面板的 systemd 方式（备选）

也有实例（包括现网）用「**systemd + run-app.sh + env.sh**」跑的，跟本包 `config/` 里三个模板一一对应：

1. 目录用 `/opt/tgg/`（放 `tgg-app.jar`、`env.sh`、`run-app.sh`）；
2. 把 `config/tgg-bot.service` 拷到 `/etc/systemd/system/`，核对里面的路径 →
   `systemctl daemon-reload && systemctl enable --now tgg-bot`；
3. `run-app.sh` 负责读 `env.sh` 并以 nohup 方式拉起 java（内容见 `config/run-app.sh`）；
4. 验证、运维、更新的做法和第 7 章、第 10 章一样，只是把「面板按钮」换成
   `systemctl start/stop/restart tgg-bot`。

> 两种方式**不要同时管同一个 jar**（会抢 8080）。二选一就行。
