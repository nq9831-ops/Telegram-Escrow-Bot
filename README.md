# TON Escrow Toolkit · 链上担保交易

**在 Telegram 里做一笔放心的担保交易——钱锁在链上，规则谁都改不了。**

买卖双方通过 Telegram 机器人成交，钱托管在**这笔订单专属的链上合约**里：
买家付款，钱进合约；卖家放心发货；买家验收，放款。
全程不用信任对方，也不用信任平台——**你只需要相信自己在链上能核对到的事实**。

---

## 为什么可以放心

**钱不在平台的账户里。** 每一笔订单都有自己独立的链上合约，不是把所有人的钱塞进一个大账户；
放款、退款都按合约里写好的规则走，**规则公开，谁都能读**。

- **你拿得回自己的钱**：托管中的订单，任一方都可发起退款；平台停止服务也不影响——规则在链上，不依赖机器人在线。
- **平台碰不了你的钱**：合约里没有「管理员提走他人资金」的通道；资金动作只能按订单状态与双方意愿推进。
- **每步都可亲眼看**：订单页可一键跳转 TON 区块浏览器，实时核对这笔钱的余额与状态。
- **改动也受制约**：合约升级需要公示期 + 双方逃生票——**哪怕运营方被劫持，你的钱仍可撤出**。

## 怎么做一笔交易

1. **发起**：买方在机器人里发单（填入金额与对方，或直接回复对方消息），或把邀请链接发给对方、一键接单。
2. **确认**：双方在动手前先看到对方这笔交易的信用概况与风险提示。
3. **付款**：买方通过钱包签名把资金锁入本单合约（金额与去向都会在签名弹窗里明示）。
4. **交付**：卖家完成交付并在机器人里标记。
5. **放款**：买家验收后放款给卖家；放款与退款等资金动作都有**二次确认**，防手滑。
6. **有争议？** 任一方可发起争议：双方各提交陈述与证据（证据做链上存证），由独立裁决方按规则裁决；结论有冷静期、任何人都能执行，不会因某一方拖着不办而卡死。

## 功能一览

- 完整交易流：发单 → 确认 → 托管 → 交付 → 放款 / 退款，含邀请链接一键接单
- 争议处理：双方陈述、已读确认、证据上链（加盐哈希，隐私安全）
- 资金安全：资金动作二次确认；每单独立合约；链上可查可核
- 信用体系：成交信用分（五维拆解）、交易榜（默认匿名，可选公开用户名与信用维度）
- 费用透明：费率由运营方公示（默认 0%），费用台账可查
- 双入口：Telegram 机器人 + 网页/Mini App（钱包签名）
- 多币种：支持 TON 与主流稳定币（USDT）

## 安全承诺

- **不碰你的私钥**：所有签名都在你自己的钱包里完成，平台接触不到你的资产。
- **不碰你的钱**：资金在链上合约，按规则流动，不经过平台账户。
- **不夸大**：每条资金状态通知都如实区分「记账更新」与「链上到账」两个阶段——没上链就不说已到账。
- **可退出**：即使平台停止服务，按公开的链上规则，你依然可以自行取回托管中的资金。

## 常见问题

**「链上托管」和「平台保管」有什么区别？**
平台保管 = 钱在平台账户、平台说了算；链上托管 = 钱在每单独立合约里，按公开规则执行，任何人都能核对。

**平台能不能挪用资金？**
不能。合约内没有提走他人资金的函数；裁决方也只能在争议流程内按规则指示，且受「当事方签名 + 冷静期」双重制约。

**平台跑路了钱拿得回吗？**
是。托管中的订单任一方可发起退款，路径不依赖平台在线。结果取决于订单状态与合约允许的退出方式，规则全程公开。

**怎么确认遇到的不是钓鱼？**
只从官方公示渠道进入机器人；打开任意订单，用链上浏览器核对合约地址与状态——**数据对得上链上，才继续操作**。订单页提供一键核对入口。

**误把普通转账打到了合约地址？**
普通空消息转账不计入托管、也无法自动退回，请只使用订单页的「支付」入口。发现误转请立即联系运营方。

**托管后我换了钱包，还能操作吗？**
托管合约在部署时锁定双方钱包地址，合约层面不可改绑（这是防劫持的设计——能改一次，就能被改第二次）。旧钱包仍可用时：任一方都可在订单页发起退款（托管中即可退），资金退回原买方钱包，再换新钱包重新发起交易。**请务必在交易前确认钱包可用并保管好私钥**——若原钱包私钥彻底丢失，链上没有任何机制能把资金改派到新地址（这同样是「平台也动不了你的钱」的另一面）。

**交易有争议怎么办？**
发起争议后双方各自陈述与举证，由独立裁决方按既定规则裁决；全程留痕于链上，可追溯。

## 风险提示

- 链上交易不可逆：签名确认前请核对金额与地址。
- 本工具为技术工具包，任何人均可部署自己的实例——**你使用哪个实例，就以上面公示的核对方式确认该实例**。
- 加密资产价格波动与本工具无关；请自行评估合规与风险。

## 部署速查（10 步）

第一次装，别用这份速查——直接看 `docs/00-手把手部署-大白话版.md`，那份写得最细。
下面是给熟手看的路标；每一步的完整解释和排错都在 `docs/01-部署教程.md`。

1. 服务器装好**宝塔面板**；软件商店里装 Nginx、MySQL 8、Java 项目管理器，JDK 装 21
2. 面板 → 数据库：建库 `tgg_escrow`（用户 `tgg`，访问权限选 127.0.0.1），记下密码
3. 找 @BotFather 申请机器人，拿 Token 和机器人用户名；把命令表贴进去（`/setcommands`，内容见教程）
4. 准备 TON 钱包：管升级的钱包（V5R1）助记词和公钥；收 USDT 再备一个 jetton 主合约地址
5. 面板 → 文件：把 `app/tgg-app.jar` 和填好的 `env.sh` 传到 `/www/wwwroot/tgg/`，`env.sh` 权限设 600
6. 面板 → 网站 → Java 项目 → 添加：jar 选上面那个，JDK 选 21，端口 8080；
   启动命令用教程 6.3 节那种自定义写法（先 `source env.sh`，再 `exec java`）
7. 给项目绑域名，再加一条反向代理指向 `http://127.0.0.1:8080`。
   **两步都要做，只绑域名不加反代会 403**。然后用面板的 SSL 申请证书，开强制 HTTPS
8. 验证：项目状态「运行中」、日志里出现 `Started EscrowBotApplication`、教程 7.3 节的端点检查全过
9. 面板 → 计划任务：加心跳任务（每 10 分钟一次，命令在教程 8.1 节，先手动跑一遍看看结果）；
   再加一个数据库备份（每天一次）
10. Telegram 里冒烟（`/start`、`/escrow`、Mini App 各点一遍），然后照教程第 9 章的清单，
    在测试网完整走一单交易，没问题再切主网

## 安全上的几件事（动手前先看）

- `env.sh` 里有机器人 Token 和钱包助记词。权限设 600，别发给任何人，更别提交到代码仓库。
  往面板填启动命令时只写文件路径，密钥不要打字进面板。
- **合约不用你手动部署**。每笔订单的托管合约，是用户用自己的钱包签名后、程序自动部署的。
  那个「治理钱包」只管升级合约用（提案、应用，72 小时公示期加逃生票），日常交易用不到它。
- 宝塔面板本身也要加固：改默认端口、开面板 SSL、限制登录 IP（教程第 12 章）。
- 想核对合约代码有没有被动过，看 `contracts/escrow-resources/EscrowContract.hash`。
